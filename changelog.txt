Merlin Browser changelog
========================

Newest first. Each entry starts with its version on its own line, which is how
the updater finds the notes for a release. The version number itself lives in
version.txt and nowhere else.

1.5.4
  Live streams that Merlin's player plays start sooner and fail less often.
  YouTube's own player often receives a stream's address a few seconds after
  the page is ready; Merlin asked once and, finding nothing, fell back to
  yt-dlp, which is far slower. It now asks the page for several seconds
  first. That is also why a refresh sometimes seemed to fix it.
  When yt-dlp is needed, it is asked every way at the same time and the first
  answer is used, rather than one way after another. A lookup that took
  minutes when the first ways failed slowly now takes as long as the quickest
  way that works; the others are stopped once it has.
  A stream that cannot be found is reported in the bar above the page, with
  Try again, instead of a box that stops everything, and the status bar gives
  one short line rather than three long ones. The details are in
  merlin-log.txt.
  Fixed: back and forward stayed greyed out on YouTube and similar sites.
  They move between pages by rewriting the address in place; the engine kept
  each move in its history, but Merlin only refreshed the buttons when a page
  finished loading, which never happened. They now follow every change of
  address.
  Fullscreen in Merlin's player now uses Merlin's own window, which goes
  fullscreen with the player covering it. The player used to leave for a
  window of its own, which could open behind Merlin, and closing it could
  leave Merlin minimised. However fullscreen ends, Esc, F11 or the system,
  the window comes back as it was, maximised if it was maximised.
  Fixed: coming out of a page's own fullscreen, YouTube's button for one,
  turned the tab strip back on even in an app window, and left a maximised
  window un-maximised.
  Web app windows keep to their own site. A link to another site, or one that
  asks for a new tab or window, opens in a new tab of an ordinary Merlin
  window, starting one if none is open.
  While Merlin looks for a stream, the bar above the page says "Connecting to
  stream....." and nothing else.
  The shield menu lists what was blocked on the page, with a button to copy
  the list, so a page that looks broken can be checked against the blocker.
  Content blocker: $generichide and $elemhide now mean what they say, "no
  general hiding on this site" and "no hiding here". EasyList uses them for
  169 sites, YouTube among them, whose own pages the general rules break.
  They were read as plain exceptions instead, which kept the hiding and let
  every request to the site through: on YouTube, 4,033 hiding rules applied
  where 33 should. About 3,100 rules whose options Merlin cannot carry out,
  $popup, $csp, $removeparam and others, are now left out rather than applied
  far more widely than meant; a $csp rule, for one, blocked every request on
  its site. Ads and trackers are blocked as before.
  IP addresses count as sites of their own. 127.0.0.1 and 10.0.0.1 were both
  taken as the site "0.1", the same one.
  The codec engine workflow keeps Qt, the source, the build and its output
  on one drive. Its first run on GitHub failed because Chromium's build
  relates those paths to one another, and Windows has no relative path from
  one drive to another.
  Merlin's player has controls in the manner of YouTube's: a thin red progress
  bar that thickens under the pointer, full and red with a LIVE badge for a
  live stream; play and pause, volume with a slider and mute, the time, close,
  and fullscreen, over a gradient along the foot. They fade while a video plays
  and the pointer rests, and return when it moves. The keys match: space or K
  to pause, M to mute, F for fullscreen and Esc to leave it, the arrows to seek
  and change the volume, and a double click for fullscreen. They are drawn by
  Merlin, not taken from YouTube.
  Merlin's player now plays inside the page, laid over the page's own video,
  the same size, and following it as the page scrolls or resizes, instead of
  in a tab of its own. The chat and the rest of the page stay as they were,
  and an app window, which has no tab strip, is no longer upset by a player
  tab appearing in it. A small bar along its foot pauses it or closes it.
  Fixed: reloading a page did not try again. The check for an unplayable
  stream only ran when the address changed, which a reload does not do, and a
  page tried once was never tried again. Both are fixed.
  When a stream will not play, merlin-log.txt now says whether its address
  answered outside the page, and what the player's own error was, so a failure
  can be told apart from a refusal.
  A live stream the engine cannot play opens in Merlin's own player by itself,
  with no bar to click. Its address now comes from YouTube's own player in the
  page, which has already met every demand YouTube makes of a client, so for a
  live stream it holds an HLS address that plays as it is and yt-dlp is not
  needed at all. Only a response for the video on screen is used: YouTube
  changes videos without loading a new page, and the one from first load goes
  stale. yt-dlp is asked only when the page has no stream, and when every way
  of asking it fails, Merlin moves its own copy to yt-dlp's nightly build,
  where YouTube fixes usually land first, and tries once more. This works the
  same on Linux, where the same yt-dlp failure had stopped it entirely.
  Existing installs get the codec engine through an ordinary update, with no
  reinstall. After starting, Merlin checks whether its engine plays H.264; if
  not, it fetches the published build in the background, checks it against its
  SHA-256, and tells you it takes effect next time. At that next start it goes
  in before the engine loads, is checked in a separate process, and is kept
  only if it plays H.264 and AAC; otherwise the original goes back. A version
  that fails is not tried again, and "nothing published yet" is rechecked at
  most once a day, so an ordinary start costs nothing extra. Files are swapped
  by rename, so a web app window open at the time keeps working, and on Windows
  the swap waits for a start where no other Merlin has the engine open.
  The download checks and the rollback are now in merlin/codecengine.py, one
  implementation for the installers, the workflow and Merlin itself.
  tools/build-webengine-codecs.bat is gone: the GitHub workflow does the build.
  The codec engine is built by GitHub Actions rather than on anyone's own
  machine. The workflow builds the Qt WebEngine version pip installs for
  Merlin, checks on Windows that it really plays H.264 and AAC, and publishes
  it where the installers fetch it. It checks weekly and builds only for a new
  version. The steps that make Qt WebEngine build on GitHub's runners follow
  danxdigitalsolution-stack/web-engine, whose public workflow found them.
  Fixed: the local build script would have built against the Qt version PyQt6
  was compiled with rather than the one it runs on. In PyQt6 6.11 those are
  6.11.0 and 6.11.2, and the engine has to match the running one exactly.
  The installers set up Qt WebEngine with H.264 and AAC on their own. After
  installing PyQt6 they fetch the matching build published on this repository,
  check it against its SHA-256, swap it in and keep it only if it really plays
  H.264 and AAC. Nothing to do by hand, and never a reason for an install to
  fail. The build script packages its result as that release asset.
  Fixed: every Linux install into a virtualenv would have stopped at that
  step, because set -e treated its "nothing published yet" answer as an error.
  Fixed: MerlinSetup.exe did not carry the tools folder, the graphical
  uninstaller or the changelog, so installs from it had no codec step and no
  graphical uninstaller. A test now checks it carries everything install.bat
  reads.
  YouTube live can play in Merlin's own engine, as it does in Brave. Brave is
  Chromium built with H.264 and AAC compiled in; the PyQt6 wheels are built
  without them. tools\build-webengine-codecs.bat builds the matching Qt
  WebEngine with -webengine-proprietary-codecs, and tools\use-codec-engine.py
  swaps it in, keeping it only if it really plays H.264 and AAC and putting
  the original back otherwise. The installer re-applies it after a reinstall.
  On Linux, --system-qt already gives an engine with the codecs.
  Fixed: Merlin crashed as it exited on Windows. The shutdown itself finished
  cleanly, then Python's own teardown destroyed the leftover Qt objects in no
  fixed order and hit an access violation. merlin-log.txt showed it nine times
  over two days, and Windows holding the process to record each crash is very
  probably why closing seemed slow. Merlin now saves everything and ends the
  process directly once shutdown is done.
  Fixed: a restored tab could start loading during shutdown, on a page already
  released. Checks for whether a tab still exists now ask whether the object
  itself does, not just whether the tab list still holds it.
  Fixed: YouTube live still failed with "Requested format is not available"
  once Deno was in place. YouTube's ordinary web client now gets only SABR
  formats, which yt-dlp cannot download, and yt-dlp's own guide gives the way
  round it: the Safari client provides HLS formats that need no PO token, and
  HLS live streams need none at all. Merlin asks for those first, then tries
  the TV client, then yt-dlp's default. If all three fail it updates its own
  yt-dlp once and tries again, since YouTube changes often.
  yt-dlp's warnings are kept now rather than discarded, and every attempt with
  what yt-dlp said goes into merlin-log.txt. The failure message says where.
  Fixed: fetching Deno failed on Windows with "No module named 'platform'".
  Merlin.exe carries only the standard modules that were in use when it was
  built, and the package, which updates from disk, can be newer. That module
  is no longer used. More to the point, the exe now carries the standard
  library broadly, through merlin/stdlib_anchor.py, and a test fails if the
  package ever imports a standard module the exe would not have. That part
  needs the installer rebuilt; the Deno fix itself arrives with an update.
  Closing Merlin is prompt. Teardown was left to the interpreter, which
  destroys things in no particular order, and the web engine waits if a page
  outlives its profile. Pages are now released before the profile, any yt-dlp
  or Deno lookup still running is stopped rather than left to its timeout, and
  a watchdog ends the process if it is somehow still there six seconds on.
  Each step is timed in merlin-log.txt.
  Fixed: the bar above the page could barely be read in the light theme. It
  never painted its own background, so its near-white text sat on the pale
  toolbar. It does now, in colours chosen for each theme.
  An error in any part of Merlin that runs from a timer or a signal no longer
  closes the browser. PyQt ends the whole application when a Python exception
  escapes one of those, unless a handler is installed; now one is, so the
  error is written to merlin-log.txt and every window and tab stays open.
  Fixed: playing a YouTube live stream in Merlin's player failed with
  "Requested format is not available". Since late 2025 YouTube only gives its
  video formats to a client that can solve a JavaScript challenge, and yt-dlp
  needs a JavaScript runtime to do it; without one it sees only thumbnails.
  Merlin now fetches Deno, the runtime yt-dlp recommends, alongside yt-dlp,
  and names it to yt-dlp explicitly. One question covers whatever is missing.
  Merlin prefers its own copy of yt-dlp over one on the PATH, since the
  official build carries the challenge solver scripts and others may not.
  YouTube live streams play. The web engine was built without H.264, and live
  streams are usually offered in nothing else, while ordinary videos come as
  VP9, which is why only live ones failed. Qt's multimedia module ships its own
  FFmpeg, and that one decodes H.264. On a live stream the page cannot play, a
  bar above the page offers Merlin's player; yt-dlp finds the stream and
  Merlin's player plays it, with nothing else to install.
  yt-dlp is actually used now. It was listed in the README and reported in the
  codec report but nothing called it. Merlin uses one on the PATH, or offers to
  fetch the official build from GitHub on first use.
  Settings, Media offers Merlin's own player as a playback mode.
  Merlin.exe bundles Qt Multimedia. The player only imports it on first use,
  so the build has to be told, or it leaves it out. This one needs a rebuild of
  the installer to reach Windows.
  Fixed: switching theme after opening and closing tabs crashed Merlin. When a
  tab closed, a disconnect() with no arguments cut every connection its web
  view had, including the ones Qt WebEngine makes internally, which left its
  widgets half wired. Setting the application's stylesheet re-polishes every
  widget it owns, and polishing one of those touched freed memory. The
  wildcard disconnect is gone; late signals are handled where they land. The
  theme switch also carries out pending deletions first, and only restyles
  when the stylesheet actually changes, rather than once per open window.
  About Merlin has a Donate button, which opens the donation page in a tab.
  The "Built on" line has a line of its own, and the text and logo sit on the
  dialog's own background rather than a slightly darker panel.
  The log is called merlin-log.txt, and there is one of it: starts, which copy
  of the code is running, a failure to start, and the stack if Merlin is ever
  killed outright all go to the same file.
  Clicking into the address bar selects the whole address, so typing replaces
  it. A second click, once the bar has focus, places the cursor as normal.
  The new tab button shows a filled circle on hover, as the close buttons do.
  It takes the accent colour rather than red, since red on the button that
  adds a tab would read as a warning.
  Fixed: the crash log never ran on Windows. It lived in merlin-run.py, which
  is frozen into Merlin.exe when it is built, and an update from Settings only
  replaces the package on disk, never the executable. It lives in the package
  now, so an update carries it. Every start writes a line saying which copy of
  the code is running, disk or the one inside Merlin.exe, so the log answers
  that whether or not anything crashes.
  The interceptor no longer shares any dictionary with the window. It reports
  an upgrade by signal, which Qt delivers to the window's own thread, so the
  record of what an address was before upgrading is written and read on one
  thread only.
  A crash log is written to Documents\Merlin\crash.log on Windows, or the
  state folder on Linux. A hard crash inside the engine leaves nothing behind
  otherwise: the window disappears with no exception to catch. Several
  locations are tried and each is proved by actually writing to it, because
  creating a folder can succeed where writing a file cannot. The path in use
  is shown in Settings, Advanced and by --icon-check.
  Fixed: typing a bare address such as google.com or a local IP could crash,
  while the same address with https:// in front was fine. Typing it bare is
  the only path that writes to the request interceptor, and the interceptor
  runs on the engine's own thread, so a dictionary was being read on one
  thread while another resized it. Everything shared with that thread is
  behind a lock now.
  The icon files are no longer part of this package; they are maintained in
  the repository.
  Close buttons on tabs are 24 pixels rather than 16, and the ones on the
  horizontal strip match, so they can be hit with a finger.
  A --zoom option sets the page zoom for one window, which is what Chromium's
  --force-device-scale-factor is used for in a web app launcher.
  Fixed: hiding the window decorations applied to every open window at once,
  and the tick in the menu came from the saved default rather than the window
  in front of you, so in any window that differed from that default, an
  installed app above all, the toggle appeared to work backwards. It is per
  window now, and the tick always reports the window it belongs to. The
  setting is still remembered as the default for windows opened later.
  An app window has no menus. It carries back, forward, reload and a button
  for the title bar, then the window controls at the right.
  The new tab button is 38 pixels rather than 26, which is a fingertip rather
  than a pointer.
  In an app window the shields, downloads, menu and window controls sit at the
  right of the toolbar. The address bar is what used to push them there, so
  without it they bunched against the reload button.
  An installed app gets its own window class, so the desktop shows it under
  its own icon rather than grouping every app under Merlin's. The generated
  desktop entry carries a matching StartupWMClass, StartupNotify and the
  Network, WebBrowser and Utility categories.
  Settings, Advanced and --icon-check say which copy of the code is running:
  the files on disk, or the one inside Merlin.exe. An update replaces the
  files on disk, so if the executable's own copy is being used the update is
  not in effect and that is worth being able to see.
  A page installed as an app opens in a window without the browsing parts: no
  address bar, no tab strip, no home, no bookmarks and no history. Back,
  forward and reload stay, as does shields, downloads and the menu, because
  those are about the page rather than about browsing.
  Fixed: the + and close buttons on the vertical tab strip did nothing under a
  finger. The strip accepted the touch events to open itself, which stopped Qt
  turning them into the clicks its buttons rely on. It notes the touch and
  passes it on now.
  The strip closes 0.9 seconds after a finger lifts rather than three, and
  closes at once if anything else on the page is touched.
  Settings, General has a slider for how far a swipe must travel, 150 to 1200
  pixels. It takes effect on the next swipe.
  Fixed: pages on the local network would not load. The https upgrade treated
  only localhost and .local as local, so every 192.168 or 10.x address, and
  every bare machine name, was upgraded to https that the device does not
  answer. Private address ranges, link-local, .lan, .home, .internal and bare
  hostnames are all left on http now.
  Typing a machine name with a port or a path, "omv:80" or "omv/", goes to it
  rather than searching for it. A bare word on its own still searches.
  Fixed: the fallback from https back to http was missing from the file, so a
  domain that only answers on http, which forwarders often do, still failed.
  Swipe navigation needs more distance to fill the arrow, 520px rather than
  380, and 340 rather than 260 by touch. The arrow now clears after 800ms of
  no movement instead of a second.
  Fixed: vertical scrolling could navigate. The sideways budget counted where
  a finger ended up rather than how far it moved, so a scroll that went down
  and back up came out near zero and never spent it, while the wobble that
  comes with scrolling added up in one direction. Distance travelled is what
  is measured now.
  Fixed: a crash when closing a tab and then switching between restored tabs
  that were still loading. A timer set 1.5 seconds after a page load ran a
  script on the view, and if that tab had been closed in the meantime the
  callback touched a deleted object and took the process with it. Anything
  deferred now checks the tab is still open, closing a tab stops its load and
  disconnects it first, and a restored tab starts loading on the next turn of
  the event loop rather than from inside the tab-changed signal.
  Selected rows are bright on dark and dark on light, rather than another
  shade of the background.
  Fixed: updating from Settings failed on Windows when installed from
  MerlinSetup.exe, saying the copy was a built executable and could not be
  changed. It can: the files it loads are the ones on disk beside it. The
  updater now finds that folder itself rather than assuming the running import
  came from it. Linux was unaffected because there is no bundle there.
  The frameless launcher is gone: one entry, one shortcut. The title bar is a
  toggle in the menu and on Ctrl+Shift+D, so a second launcher for it was
  another thing to keep in step for no gain.
  Fixed: a page installed as an app on Windows opened merlin-run.py in a tab
  instead of the site. The shortcut handed a script path to Merlin.exe, which
  is not an interpreter and treated it as an address to open.
  Settings has a Web apps tab listing the pages installed as apps, with buttons
  to open or remove one. Removing deletes the shortcut and its icon; the site
  is untouched.
  Fixed: a selected row in a list was drawn in the palette's default highlight,
  which against the dark background was indistinguishable from an unselected
  one. Lists now have their own selected and hover colours in both themes.
  A graphical uninstaller, uninstall-gui.py and uninstall-gui.bat, installed
  alongside the text one. It runs the same script and offers to keep or delete
  the profile.
  Fixed: installing a page as an app on Linux made a shortcut that did nothing.
  A percent sign begins a field code in a desktop entry, so any percent encoded
  address, which is most of them, produced an invalid code and the launcher
  refused to start it without saying so. Percent signs are doubled now, as the
  specification asks, and the entry uses the installed launcher rather than a
  path to a particular interpreter, so it survives a reinstall.
  The vertical tab strip opens on touch. It only ever watched for a mouse
  pointer, and touch does not move one, so on a touchscreen there was no way to
  expand it. A touch now opens it and holds it open for a few seconds, since a
  finger leaving the screen is not the same as a pointer leaving the panel.
  Smooth page corners are off by default on a plain X11 session. The overlay
  that draws them needs a compositing manager to blend it; without one it shows
  the desktop through itself and the corners come out as a thin line. Windows
  and Wayland always composite, so it stays on there.
  The icon fills its tile: the wizard now uses 98 per cent of the height, with
  two pixels clear top and bottom, which is as large as it goes before the
  hat's point or the beard touch the edge.
  Fixed: the taskbar icon on Windows, again. Merlin.exe is built from
  merlin-run.py with the package inside it, which is the arrangement that
  produces a working executable. Excluding the package to make updates simpler
  broke the build, so the installer fell back to the interpreter and the icon
  reverted to Python's.
  Updates still need no rebuild: merlin-run.py prefers a copy of the package
  found on disk beside the executable, and falls back to the bundled one if it
  is missing, so an interrupted update cannot stop Merlin starting.
  Fixed: a second, transparent window appeared alongside Merlin. The corner
  overlay had been made an ordinary top level window, which the window manager
  lists and gives a taskbar button. It is a tool window again, owned by the
  browser window and not listed.
  Fixed: Merlin.exe was not being built, because the boot script's imports did
  not tell PyInstaller that Qt was needed, so the installer fell back to the
  interpreter and the taskbar showed Python's icon. The fallback now says so
  loudly instead of passing unnoticed.
  Restored tabs show a placeholder icon and the site's host until they are
  opened, so a restored window no longer looks like it has one tab.
  The installer says loudly when Merlin.exe could not be built, and Settings,
  Advanced repeats it, because that is when the taskbar shows Python's icon.
  Merlin.exe no longer carries the application inside it. It carries the
  interpreter, Qt and the web engine, and loads the merlin package from the
  app folder on disk. Updates replace those files and take effect on the next
  launch: no rebuild, and nobody has to run install.bat again.
  Settings, Updates therefore works on a built copy, which it could not before.
  A rebuild is only needed when a dependency changes, and this file will say so
  when that happens.

1.5.3
  Fixed: session restore only remembered the tabs that had been loaded. A
  restored tab does not load until it is selected, and until then its address
  is pending rather than current, so quitting without visiting them saved only
  the first one.
  Reopening a closed tab works for tabs that were never visited.
  GPU fingerprinting protection for WebGL and WebGPU.
  The https upgrade falls back to http for hosts that only answer there, which
  domain forwarders often do.
  The installer reports the pip already present and offers to replace it rather
  than upgrading silently.
  version.txt now holds only the version; release notes live here.

1.5.2
  Graphical installer, which runs the same scripts as the text one and shows
  the same steps with the detail behind a toggle. It can be built into a single
  MerlinSetup.exe with tools\build-installer.bat.
  The installer no longer flashes a console window when run from the GUI.
  Speak to search on the new tab page, recognised locally with Vosk.
  Saved logins, encrypted by DPAPI on Windows or the system keyring elsewhere,
  imported from a CSV exported by another browser.
  Import bookmarks and history from Chrome, Edge, Brave, Vivaldi, Opera,
  Chromium and Firefox.
  Updates can be downloaded and installed in place from Settings.
  Tabs can be reordered and dragged out into their own window.
  Downloads and history dropdowns; the menu button moved to the far right.
  A clock in the status bar, and a theme that can follow the time of day.
  Random new tab background option.
  Smooth, antialiased page corners drawn by an overlay rather than a mask.
  Fixed: the taskbar icon on Windows, which needed a real executable rather
  than a script run through an interpreter.
  Fixed: sites that redirect to another domain were blocked by the content
  blocker, which should never filter a top level page.
  Fixed: the address bar was empty for a tab opened from a link.
  Fixed: page scrolling could half fill the back and forward gesture arrows.
